# Three-pass bug audit — October 25, 2026

Local fixes; not published. The initial full suite passed all 391 tests. The
audit then exercised failures that the normal success-path tests did not cover.

## Pass 1: loading saves

Reproduced two startup failures from partially valid optional save metadata:
an inbox without `seen` crashed reconciliation, and a null sponsorship entry
crashed income calculation. Invalid numeric sponsorship values could also
poison income. Both new regression tests failed before the fix.

`save-optional.ts` now normalizes these blocks independently during `readSave`.
Valid deals, money, players, message text, read/archive flags, reservations and
deduplication IDs survive. Invalid optional entries are excluded; valid campaign
data is retained. Unknown inbox page actions cannot navigate to a blank page.
This is recovery for these optional blocks, not arbitrary corrupt-save repair.

## Pass 2: worker crashes and navigation locks

The All-Star spectator worker lacked an error handler: a loading/runtime failure
could leave its busy state and navigation locked indefinitely. Worker construction
and request cloning could also throw before live/tournament error handlers were
installed. Message decoding errors were unhandled in all four consumers.

`simulation-worker.ts` handles construction, posting, load/runtime and decoding
failures through one terminal callback and suppresses late results after failure.
Draft, live, tournament and exhibition screens use it. The All-Star start flow
also no longer overwrites a synchronous failure with a new busy state. Existing
map/tournament retry controls remain available; failures record no result.

Fault-injection tests cover construction, posting, load and decoding errors,
duplicate failure events, late completion and a successful message. Disposable
browser fixtures verify constructor/decoding recovery and an All-Star error
returning to an unlocked screen with its Watch button available.

## Pass 3: settlement and preservation of played maps

Reproduced a tournament settlement that consumed player energy and recorded a
match even though an earlier scrim prevented its clock advance. It also mutated
the input campaign. Settlement now rejects this case before changing player or
campaign state. Non-finite, zero and negative map durations are rejected before
recording. Two regression tests failed before these fixes; a third verifies
successful elapsed time, input immutability and duplicate-delivery safety.

Completed drafts previously latched their completion flag before the parent
confirmed settlement. Calendar/exhibition flows could discard the completed maps
on failure, while scrims could remain on an unresponsive Finish button. Completion
now accepts explicit success/failure; failed or thrown submissions retain the
same maps and allow retry. Calendar, scrim and exhibition parents propagate the
outcome and only dismiss the match after success.

A disposable browser fixture rejected its first submission, threw on its second,
accepted its third and ignored a fourth click. It retained the same map throughout;
the fixture's state confirmed exactly three submissions and one success.

### Long live maps

During this pass the existing balance job logged one automatic time-limit failure:
patch `2013.1`, seed `773610270`. An independent reproduction reached the same
three-hour cutoff with neither Ancient destroyed. Extending that diagnostic via
normal engine steps produced a real Dire victory at **3:11:25**. It was not a
permanent stalemate or an invented result.

The live viewer previously treated this cutoff as fatal, terminated its worker and
offered to restart, losing the running map and its accepted actions. A live
automatic-limit response now retains its session and returns paused controls,
with an explanation that the manager can resume or step forward. Unexpected
engine errors still surface normally. A regression test checks retained state,
inspection target, Auto Glyph preference, subsequent stepping and unexpected-error
propagation. Browser QA confirms Simulate remainder becomes available again,
Resume and Advance 1 minute work, and the same map advances beyond three hours.

The headless automatic three-hour limit and calibration completion gates remain
unchanged. The running balance job still reports that failed sample; this audit
does not certify balance or remove a legitimate validation failure.
